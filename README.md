# resume-maker · SynRes-KR

이력 결측치 탐색 연구를 위한 **한국어 합성 이력서 데이터셋 생성기**와,
결측 탐색부터 보완까지의 동작을 문서로 출력하는 도구 모음.

특허 출원 *「이력 결측치 탐색 및 데이터 통합 기반의 상호작용형 이력서 자동 생성
시스템 및 그 방법」* (관리번호 P-2026-00131)의 구성요소를 실제 데이터로 검증하기
위해 만들었다.

외부 채용 사이트를 크롤링하지 않는다. 직무 분류 체계와 일반적인 이력서 구조만
참조한 자체 사전으로 생성하며, 등장하는 인명·회사명·학교명은 모두 가상이다.

---

## 무엇을 만드는가

핵심은 결측을 **찾는** 것이 아니라 **심는** 것이다.

```
① gold      결측이 전혀 없는 완전한 이력서를 생성
② inject    3+4종의 결측을 통제된 확률로 주입하고 위치·유형·정답을 라벨로 기록
③ render    같은 이력서를 대화 / 파일 / 웹프로필 3채널로 렌더링
```

`gold_answer`가 라벨에 함께 남기 때문에, 실제 사용자 없이도
**질문 → 답변 → 병합 → 완성도 측정** 루프 전체를 시뮬레이션할 수 있다.

## 빠른 시작

```bash
# 데이터셋 생성 (Python 표준 라이브러리만 사용)
python3 src/generate.py --n 400 --seed 42 --out output/resumes.jsonl

# 라벨 정합성 검증 (규칙 기반 탐지기)
python3 src/detect_eval.py --data output/resumes.jsonl

# 질문 예산 정책 비교 (탐지기를 루프에 포함)
python3 src/policy_eval.py --data output/resumes.jsonl --budget 10 --discovery

# 날짜 보정 관례 절제 실험
python3 src/date_ablation.py --data output/resumes.jsonl

# 원문 텍스트 LLM 탐지 (API 키 필요)
export ANTHROPIC_API_KEY=...
python3 src/llm_detect.py --data output/resumes.jsonl --n 60 --workers 10

# 예시 Word 문서 일괄 생성 (Node.js + docx 필요)
npm install
python3 src/build_examples.py --data output/resumes.jsonl
```

## 지원자 구성

| 축 | 분포 |
|---|---|
| 진입 유형 | 경력직 81% / 무경력 신입 19% |
| 결측 0건(음성) 레코드 | 21.2% |
| 최종 학위 | 학사 56% · 전문학사 18% · 석사 14% · 고졸 10% · 박사 3% |
| 총 경력 | 중앙값 약 6년, 10년 이상 약 30% |
| 대외활동 | 신입 100%, 시니어로 갈수록 감소 |
| 해외 경험 | 전체 약 25% (고졸 제외) |

경력 타임라인은 **현재 시점에서 과거로 역산**한다. 마지막 경력은 모두
현재 진행 중이거나 최근에 종료된 상태이므로, 데이터가 오래되어 "지금 구직 중인
사람의 이력서"로 보이지 않는 문제가 없다.

무경력 신입은 `careers`가 비고 `personal_projects`(개인·졸업 프로젝트)와
대외활동이 서사의 중심이 된다. 고졸은 `HS_MAJOR`에 정의된 8개 직군에서만
생성되며, 일반고는 학과 대신 계열(인문/자연)을 갖는다.

## 결측치 유형

| 라벨 | 설명 | 명세서 대응 |
|---|---|---|
| `TEMPORAL_GAP` | 경력 사이의 기간적 공백기 | 기간적 공백기 탐색부 (1211) |
| `POST_GRAD_GAP` | 졸업 후 현재까지의 구직 공백 | 1211 확장 |
| `ROLE_OMISSION` | 경력 구간의 직무 정보 누락 | 직무 누락 탐색부 (1212) |
| `ACHIEVEMENT_OMISSION` | 프로젝트의 역할·정량성과·결과 누락 | 성과 누락 탐색부 (1213) |
| `THESIS_OMISSION` | 석·박사 학위 연구주제 누락 | 1213 확장 |
| `EXTRACURRICULAR_OMISSION` | 대외활동 역할·성과 누락 | 1213 확장 |
| `DATE_INCOMPLETE` | 기간 해상도 저하 (`2021-03` → `2021년`) | 1211의 날짜 보정 대상 |

## 생성 파라미터

| 인자 | 기본값 | 의미 |
|---|---|---|
| `--n` | 400 | 생성할 이력서 수 |
| `--seed` | 42 | 난수 시드 (재현성) |
| `--gap-threshold` | 3 | 공백 판단 기준값(개월). 청구항 4의 "공백 판단 기준값" |
| `--p-gap` | 0.75 | 공백을 메우던 활동 항목 제거 확률 |
| `--p-role` | 0.30 | 직무 정보 누락 주입 확률 (경력 단위) |
| `--p-ach` | 0.45 | 성과 누락 주입 확률 (프로젝트 단위) |
| `--p-date` | 0.10 | 기간 해상도 저하 확률 |
| `--p-thesis` | 0.40 | 학위 연구주제 누락 확률 |
| `--p-extra` | 0.45 | 대외활동 역할·성과 누락 확률 |
| `--p-clean` | 0.18 | 결측이 전혀 없는 음성 샘플 비율 |

`gold`는 정의상 결측이 없는 완전판이다. 모든 누락은 `inject()` 단계에서만
발생하므로, 관측판에서 비어 있는 필드는 전부 라벨과 1:1로 대응한다.

A는 라벨의 `gold_answer`를 구어체로 되돌린 것이고, 추출 줄은 답변 파싱부(131)가
필드 단위로 분해한 결과에 해당한다. 개별 실행은 다음과 같다.

## 규칙 기반 베이스라인 성능

`detect_eval.py`는 **구조화된 `observed` JSON**을 입력으로 받는다. 즉 데이터 형식
변환부(114)가 완벽히 동작했다는 가정이며, 여기서 나오는 수치는 **상한선**이자
라벨 정합성 검증용이다. 논문의 실제 태스크는 `renders` 원문 텍스트에서 곧바로
결측을 탐지하는 것이다.

| 유형 | P | R | F1 |
|---|---|---|---|
| TEMPORAL_GAP | 0.992 | 0.909 | 0.948 |
| POST_GRAD_GAP | 1.000 | 1.000 | 1.000 |
| ROLE_OMISSION | 1.000 | 1.000 | 1.000 |
| ACHIEVEMENT_OMISSION | 1.000 | 1.000 | 1.000 |
| THESIS_OMISSION | 1.000 | 1.000 | 1.000 |
| EXTRACURRICULAR_OMISSION | 1.000 | 1.000 | 1.000 |
| DATE_INCOMPLETE | 1.000 | 1.000 | 1.000 |
| **micro** | **0.999** | **0.988** | **0.993** |

TEMPORAL_GAP 재현율이 1.0이 아닌 것은 버그가 아니다. 기간이 `2021년`처럼 연 단위로만
기재된 경력을 날짜 보정 규칙으로 채우면 그 안에 있던 공백이 덮여버리기 때문이다.
**기간 해상도 저하가 공백 탐지 실패로 이어진다**는 관찰은 그대로 논문에 쓸 수 있다.

## 날짜 보정 관례가 공백 탐지를 결정한다

연 단위로만 적힌 기간(`2021년`)을 월로 되돌리는 방법은 자유 선택인데, 그 선택이 공백을
살리거나 지운다. 연 단위 기간을 포함한 113건 기준.

| 관례 | P | R | F1 |
|---|---|---|---|
| drop (구간에서 제외) | 0.500 | 0.538 | 0.518 |
| expand (1월~12월) | 1.000 | 0.782 | 0.877 |
| narrow (12월~1월) | 0.522 | 1.000 | 0.686 |
| **날짜 질문 선행 응답 후** | **1.000** | **1.000** | **1.000** |

`expand` 는 정밀도를 지키지만 공백의 **21.8%를 조용히 삼킨다**. `narrow` 는 다 찾지만 허위
공백 109건을 만든다. 해법은 더 나은 관례가 아니라 **두 질문에 순서가 있다는 것**이다.
날짜를 먼저 물으면 공백 탐지가 정확해진다. 현재 `policy_eval.py` 의 중요도 정렬은
`TEMPORAL_GAP` 을 `DATE_INCOMPLETE` 보다 먼저 묻는데, 이는 거꾸로다.

## 원문 텍스트로부터의 탐지

`renders` 원문을 그대로 LLM(claude-sonnet-5)에 주고 결측을 찾게 한 결과. 층화 표본 60건
× 3채널. 웹 프로필은 학력 섹션이 없어 학위·졸업공백 유형을 채점에서 제외했다.

| 입력 | P | R | F1 | 음성 오탐 |
|---|---|---|---|---|
| 정규화된 레코드 (규칙, 상한선) | 0.999 | 0.988 | 0.993 | 0 |
| 대화 기록 (LLM) | 0.795 | 0.385 | 0.519 | 8 |
| 문서형 이력서 (LLM) | 0.786 | 0.410 | 0.539 | 7 |
| 웹 프로필 (LLM) | 0.636 | 0.432 | 0.514 | 22 |

**손실은 거의 전부 재현율이다.** 직무명 누락 재현율 0.278, 성과 누락 0.328인 반면 졸업 후
공백은 0.818이다. 졸업 공백은 인쇄된 두 날짜 사이의 모순으로 보이지만, 직무명 누락은 오직
부재로만 보인다. **부재에는 표면형이 없다** — 이력서를 통째로 모델에게 읽히는 대신 정규화된
레코드 위에서 결정적으로 탐지해야 하는 이유다.

## 질문 예산 정책 비교

`gold_answer` 를 모의 응답자로, **탐지기가 찾은 것만 물을 수 있는** 조건에서 돌린 결과다.
`|M| >= 6` 부분집합(n=165) 기준.

| 정책 | AUC(K=10) | k*(0.8) |
|---|---|---|
| 전량 질의 | 1.000 | 8.47 |
| 무작위 | 0.883 | 3.20 |
| 순차 스윕 | 0.884 | 3.24 |
| 중요도 (유형 우선순위) | 0.890 | 3.13 |
| **이득 (가중치 × 필드 수)** | **0.907** | **2.38** |
| 이득 + 의존관계 | 0.902 | 2.55 |

**정렬하느냐보다 무엇으로 정렬하느냐가 중요하다.** 중요도 정렬은 무작위 대비 0.007에
그치지만 이득 정렬은 0.024를 얻고 질문 수를 3.20 → 2.38로 줄인다. 가중치와 필드 수 모두
질문 시점에 관측 가능하므로 **오라클이 아니라 배포 가능한 정책**이다.

날짜 질문을 먼저 묻는 `이득+의존` 은 오히려 **더 나쁘다**(0.902). 의존관계는 탐지 수준에서는
실재하지만 잠금 해제되는 인스턴스가 전체의 1.1%뿐이라, 이른 턴을 쓸 만큼 잦지 않다.
날짜 질문과 그것이 가리는 공백은 같은 경력 항목이므로 **하나의 프롬프트로 합치는 편**이 낫다.

## 알려진 한계

- 완전 합성 데이터이므로 실제 이력서의 표현 다양성·오타·비정형성을 과소 반영한다.
- 성과 수치는 지표별 범위에서 균등 추출한 값이며 직군별 실제 분포와 다르다.
- 결측은 통제된 확률로 주입되었고, 실제 구직자의 누락 패턴과 상관 구조가 다르다.
- 텍스트 수준 평가는 120건·단일 모델이라 직접/하이브리드 분리는 보이지만 모델 서열화에는 부족하다.
- 하이브리드가 복사하라고 한 필드(연구 주제 등)를 지어내는 사례가 있다. 정규화 결과의 각
  필드가 원문 어느 구간에서 왔는지 검증하는 단계가 필요하다.
- 재직 구간 **내부**의 프로젝트 공백(프리랜서·1인 법인에서 구조적으로 발생)은
  현재 탐지 대상이 아니다.
- 예산 실험의 모의 응답자는 항상·정확히·완전히 답한다. 실제 지원자의 거부와 부분 응답을
  반영하지 않으므로 완성 곡선은 상한이다.
